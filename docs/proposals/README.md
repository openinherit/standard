These documents describe potential future directions for INHERIT. They are not part of the current standard and carry no commitment to implementation.

**All proposals are tracked via [GitHub Issues](https://github.com/openinherit/standard/issues).**

## When to write a proposal vs file an issue

**Start with a GitHub issue.** Bugs, feature requests, and short ideas all belong there. Most work can be discussed and resolved entirely within an issue.

A proposal document is only needed when an idea is too complex to reason about in an issue thread — typically when it involves trade-offs across multiple schemas, alternative design approaches, or worked examples showing how the feature would look in practice. If it fits in a few paragraphs, it's an issue. If it needs sections and examples, write a proposal and link the issue to it.

Every proposal document must include a `github_issue` field in its frontmatter linking to the tracking issue.
